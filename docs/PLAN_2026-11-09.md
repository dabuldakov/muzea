## Этапы

### P0 — стабильность и потери данных (2–3 дня)

1. **NET.07** — не очищать список при фоновом обновлении, не показывать
   спиннер, если данные уже есть. Причина мигания: состояние загрузки
   перерисовывает пустой список; нужно разделить «первая загрузка» и «refresh».
2. **MEDIA.08** — сохранять выбранные вложения и очередь загрузки на диск,
   повторять при появлении сети, не удалять при выходе из чата. Сервер уже
   принимает файлы; нужен только клиентский outbox для медиа.
3. **MSG.11** — черновик текста на чат: сохранять при уходе/паузе, подставлять
   при возврате, очищать после отправки. Автоотправки нет.
4. **MSG.12** — стабильная прокрутка: не сбрасывать позицию при incremental
   sync, сохранять якорь по messageUuid и offset.

### P1 — чат и реакции (2 дня)

5. **UI.10** — `maxLines=6`, адаптивная высота, тот же лимит в режиме
   редактирования.
6. **UI.11** — скрывать `bottomNavigation` только на экране переписки,
   восстанавливать при выходе, учитывать insets.
7. **MSG.16** — реакции: таблица `message_reactions`, API добавления/снятия,
   поле в DTO сообщений, отображение под пузырём. Нужны миграция и проверка
   в polling/`after`; старые клиенты поле игнорируют.

### P2 — группы и контакты (2 дня)

8. **MSG.13** — переименование группы: API (проверить наличие), доступ только
   владельцу/админу, обновление заголовка и кэша списка.
9. **MSG.14** — удаление участника: API, проверка прав, обновление состава и
   системное сообщение (если принято).
10. **MSG.15** — удаление контакта: API, подтверждение, обновление списка и
    приватных чатов.

### P3 — навигация и композер (2–3 дня)

11. **UI.12** — одна кнопка: смайлик открывает две вкладки — эмодзи и GIF.
12. **UI.13** — скрепка/«+» справа от поля, увеличить ширину поля, уменьшить
    отступы кнопок.
13. **UI.14** — шестерёнка в нижнем меню вместо профиля; профиль — раздел
    настроек.
14. **UI.15** — порядок вкладок в настройках, хранение в prefs, старт с первой.

## Риски и зависимости

- **Реакции** (MSG.16) — единственный пункт с обязательной миграцией БД и
  изменением API; без сервера его не сделать.
- **Медиа-очередь** (MEDIA.08) — нужна аккуратная очистка файлов, иначе
  разрастётся хранилище.
- **Удаление участника/контакта** — проверить права и поведение при
  одновременном изменении с другого устройства.
- **Скрытие вкладок** (UI.11) — не ломать deep links и возврат назад.
- **Порядок вкладок** (UI.15) — миграция настроек между версиями.

## Критерии готовности

- P0: уход из чата и возврат не теряет текст/медиа; при фоновом sync список не
  мигает; прокрутка не прыгает.
- P1: 6 строк ввода; в чате нет нижней панели; реакции видны всем участникам.
- P2: владелец меняет название, удаляет участника; контакт удаляется с
  подтверждением.
- P3: эмодзи и GIF в одной кнопке; композер шире; порядок вкладок сохраняется.
