# Вложения в чате и режимы отправки (аудио/видео)

> **Статус:** реализовано (1.7.9). Вложения: «+» с выбором фото/видео/аудио/
> документа, загрузка с превью и прогрессом, пузыри для всех типов,
> полноэкранный просмотр фото/видео/аудио, скачивание документов, серверная
> валидация и Range-запросы. Режимы кнопки: текст/голос/видео; голосовые по
> удержанию до 5 минут, видео-кружки фронтальной камерой до 60 секунд.

План реализации. Сначала — что уже есть и где дыры, затем этапы, оценка и вопросы.

## 1. Готовность

### Бэкенд чата

Есть почти всё «железо», но нет связки с сообщением:

- таблица `attachments` и сущность с типами `IMAGE / VIDEO / GIF / AUDIO / DOCUMENT / OTHER`;
- размер, MIME, ширина/высота/длительность, превью, MP4-вариант;
- `POST /api/attachments/upload?chatUuid=...` — загрузка в MinIO с проверкой доступа к чату;
- `GET /api/attachments/{uuid}` — скачивание с проверкой доступа;
- `GET /api/attachments/{uuid}/preview`, `DELETE`, список вложений чата/сообщения;
- очистка «сирот» старше 24 часов;
- в `Message.MessageType` уже есть `IMAGE, VIDEO, AUDIO, FILE`;
- в `SendMessageRequestDto` есть `attachments: List<UUID>`.

**Критично: связка не работает.**

- `MessageService.sendMessage(...)` принимает `attachmentUuids`, но **не использует их**;
- `AttachmentService.attachToMessage(...)` нигде не вызывается;
- у загруженного файла `messageId` остаётся `null`, поэтому `attachAttachments(...)` в ответе ничего не находит;
- загруженные файлы удаляются как «сироты» через 24 часа.

То есть сначала нужно починить склейку «загрузил → прикрепил к сообщению», иначе остальное не имеет смысла.

**Чего ещё нет:**

- валидации MIME/расширения/размера — сейчас можно загрузить что угодно в пределах 5 МБ;
- лимита на число вложений;
- превью для видео/аудио (thumbnail/duration);
- Range-запросов для плеера (сейчас отдаётся `Resource` целиком);
- осмысленного текста push для сообщений без текста («📷 Фото» вместо пустоты);
- ограничений nginx/Spring под крупные файлы: servlet `max-file-size: 5MB`, nginx `64m`.

### Android-клиент

- Отправка только текста и GIF; загрузки вложений в чат нет.
- `MessageAttachment` уже умеет `fileUrl/thumbnailUrl/type/width/height/mp4Url` — база для рендера есть.
- Рендера изображений/видео/аудио/документов в пузырях нет (только GIF).
- Нет `CAMERA` / `RECORD_AUDIO` в манифесте, нет CameraX и записи звука.
- Пикеры уже используются в других экранах: `PickVisualMedia` (фото/видео), `OpenDocument` (файлы) — можно переиспользовать.
- Glide уже умеет авторизованные картинки с `chat-muzea.su`, Media3 — авторизованное видео через `VideoPlayerHelper`.

## 2. UX: что делаем

### 2.1. Кнопка «+»

Слева от поля ввода, перед текстом:

```
[+] [ Поле ввода сообщения........ ] [GIF] [→]
```

По нажатию — нижняя шторка:

- **Фото** — мультивыбор из галереи (до 10);
- **Видео** — выбор одного видео из галереи;
- **Аудио** — выбор аудиофайла;
- **Файл** — PDF, TXT, DOC/DOCX, XLS/XLSX, PPT/PPTX, CSV;
- (опционально) **Камера** — снять фото/видео сразу.

После выбора — превью-полоса над полем ввода: миниатюра, имя, размер, прогресс загрузки, крестик «убрать». Отправка блокируется, пока файл не загружен (или разрешаем отправку с прогрессом и догрузкой — см. вопросы).

### 2.2. Пузыри в переписке

- **Фото**: сетка 1–10, скруглённые углы, тап — полноэкранный просмотр с зумом/свайпом.
- **Видео**: превью с кнопкой Play, длительность; тап — полноэкранный плеер (Media3, авторизация уже есть).
- **Аудиофайл**: карточка с иконкой, именем, размером; play/pause, перемотка, время.
- **Документ**: карточка с иконкой типа, именем, размером; тап — скачать/открыть через `FileProvider`.
- Входящие и исходящие — по одной схеме, с учётом цвета пузыря.

### 2.3. Три режима кнопки отправки (отдельная фича)

```
Текстовый режим:  [→]   — отправить текст
Режим голоса:     [🎤]  — тап переключает режим, удержание пишет голосовое
Режим видео:      [🎥]  — тап переключает режим, удержание пишет видео-кружок
```

- Пока в поле есть текст — кнопка остаётся «отправить», чтобы не мешать.
- Удержание микрофона: запись, таймер, «отпустите для отправки», свайп вверх/в сторону — отмена.
- Удержание видео: запись с фронтальной камеры, круглая маска, до 60 секунд.
- Короткое нажатие (< 1 c) — отмена, чтобы не отправлять пустое.
- Оба типа — обычные сообщения: их можно пожаловаться, удалить, они участвуют в статусах.

Это отдельный крупный этап: камера, разрешения, запись, волна, плеер, хранение.

## 3. Предлагаемые ограничения

| Тип | Форматы | Размер | Дополнительно |
|-----|---------|--------|----------------|
| Фото | jpg, jpeg, png, webp | до 50 МБ каждое, до 10 шт. | клиент сжимает до 2048 px по длинной стороне |
| Видео | mp4 (H.264/AAC) | до 200 МБ, до 3 мин | без транскодинга на сервере |
| Аудио | mp3, m4a/aac, ogg/opus, wav | до 50 МБ, до 10 мин | — |
| Документы | pdf, txt, doc/docx, xls/xlsx, ppt/pptx, csv | до 100 МБ | без архивов, exe, html, svg |
| На сообщение | — | до 10 вложений, суммарно ≤ 64 МБ | — |

Запрещаем: `.exe`, `.apk`, `.bat`, `.sh`, `.js`, `.html`, `.svg`, архивы — чтобы не превращать чат в файлопомойку и не ловить XSS через SVG/HTML.

Проверка на сервере: MIME по «магическим байтам» (Apache Tika или собственная проверка сигнатур), расширение — по белому списку, размер — по типу. Не доверяем `Content-Type` от клиента.

## 4. API и бэкенд

### 4.1. Склейка вложения с сообщением

В `MessageService.sendMessage`:

1. для каждого `attachmentUuid`:
   - найти вложение;
   - проверить, что оно в этом чате и загружено этим пользователем;
   - проверить, что ещё не привязано к другому сообщению;
2. выставить `messageId`, `hasAttachments = true`;
3. тип сообщения (`IMAGE/VIDEO/AUDIO/FILE`) вывести из типа вложений, если клиент не передал;
4. отдать вложения в `MessageDto` (уже есть `attachAttachments`).

Ошибки: чужое вложение, другой чат, уже привязано → `400/403`.

### 4.2. Валидация загрузки

- белый список MIME + сигнатуры;
- лимиты по типу и общий;
- лимит числа вложений на сообщение;
- `Content-Disposition` уже санитизируется (`FileNames`);
- для изображений — проверить, что это действительно изображение (заголовок/размеры), защита от «zip-бомб»;
- при отказе — понятная ошибка, файл не сохраняется.

### 4.3. Метаданные и превью

- ширина/высота/длительность: клиент извлекает при выборе (`MediaMetadataRetriever`/`BitmapFactory`) и передаёт в multipart-полях;
- превью видео/фото: клиент генерирует и загружает отдельным полем (или вторым запросом);
- сервер сохраняет `thumbnailUrl`, `duration`, `width`, `height`.

Так не нужен ffmpeg на сервере — меньше вес контейнера и рисков.

### 4.4. Отдача файлов

- `GET /api/attachments/{uuid}` — поддержать `Range` (Spring `ResourceRegion`), иначе перемотка видео/аудио не работает;
- корректный `Content-Type`, `Accept-Ranges`, `Content-Length`, `Cache-Control` для превью;
- авторизация остаётся: Glide и Media3 уже шлют Bearer на `chat-muzea.su`.

### 4.5. Push и последнее сообщение

Для сообщений без текста:
- push: «📷 Фото», «🎥 Видео», «🎤 Аудио», «📎 Документ»;
- `chat.last_message_text` — тот же человекочитаемый текст, чтобы список чатов не был пустым.

### 4.6. Тесты бэкенда

- загрузка разрешённого/запрещённого типа;
- превышение размера;
- привязка вложения к сообщению, повторная привязка, чужой чат;
- скачивание с Range и без;
- удаление сообщения → удаление файлов;
- push-текст для каждого типа.

## 5. Клиент

### 5.1. Данные

- `AttachmentResponse`/`MessageAttachment` расширить: `attachmentUuid`, `fileName`, `fileSize`, `mimeType`, `duration`.
- `SendMessageRequest` — добавить `attachments: List<String>` (UUID).
- `ChatApiService`:
  - `uploadAttachment(@Part file, @Part thumbnail?, @Query("chatUuid"), @Part("width"), ...)`;
  - `sendMessage` уже принимает текст/тип, добавить UUID-ы.
- `MessageRepository`: `uploadAttachment(uri, meta): Flow<Resource<Attachment>>`, `sendMessage(chatUuid, text, attachments)`.
- Загрузка — через `ContentResolver` → временный файл в `cacheDir`, имя санитизируется, MIME определяется по содержимому.

### 5.2. Экран чата

- Кнопка «+» и шторка выбора.
- `PickMultipleVisualMedia` для фото, `PickVisualMedia.VideoOnly` для видео, `OpenDocument` с MIME-фильтрами для аудио/документов.
- Превью-полоса с прогрессом (`ProgressBar`/проценты), отмена загрузки.
- Состояние «загружается» в ViewModel: `pendingAttachments`.
- Отправка: сначала все файлы, затем сообщение с UUID-ами; при ошибке — сообщение не отправляется, превью остаётся с кнопкой «повторить».
- Рендер вложений в адаптере: image grid, video preview, audio card, document card.
- Полноэкранный просмотр: фото — зум; видео — Media3; аудио — play/seek; документ — `ACTION_VIEW` через `FileProvider`.
- Локализация: 14 языков (кнопки, ошибки, типы файлов, «Скачать», «Открыть», «Отмена загрузки» и т.п.).

### 5.3. Тесты клиента

- маппинг вложений, определение типа по MIME;
- ViewModel: загрузка → отправка, ошибка загрузки, отмена, повтор;
- лимиты (не больше 10, размер);
- UI-тесты — по желанию (фото/видео/аудио/документ в пузыре).

## 6. Этапы и оценка

| Этап | Что входит | Оценка |
|------|------------|--------|
| A1. Склейка и безопасность | фикс `attachToMessage`, валидация, лимиты, push-текст, тесты | 2–3 дня |
| A2. Клиент: фото и документы | «+», шторка, выбор, загрузка, превью, пузыри, открытие | 3–4 дня |
| A3. Клиент: видео и аудио | плееры, превью, Range на сервере, прогресс | 2–3 дня |
| A4. Проверка | два устройства, лимиты, ошибки сети, регресс | 1–2 дня |
| **Итого вложения** | | **8–12 дней** |
| B. Три режима + голосовые и видео-кружки | камера, запись, волна, круглый плеер, разрешения, бэкенд-типы | **6–8 дней** |

Можно резать:

- **MVP за 4–5 дней**: склейка + фото + документы (без видео/аудио).
- Потом видео/аудиофайлы (+2–3 дня).
- Голосовые и видео-кружки — отдельным релизом.

## 7. Риски и крайние случаи

- **Большие файлы**: обрыв загрузки, таймауты, память. Загружать потоково, не читать файл целиком в `ByteArray`.
- **Очистка сирот**: если пользователь выбрал файл, но не отправил — через 24 часа сервер удалит; клиент должен уметь повторить.
- **Права доступа**: скачивание только участникам чата; при удалении сообщения/чата файлы удаляются.
- **Модерация**: вложения — часть сообщения, жалоба уже работает; модератор должен видеть файл и уметь удалить.
- **Play**: UGC-политика покрывает вложения; Data safety не меняется (контент уже декларирован), но стоит проверить формулировки.
- **Приватность**: EXIF (геолокация) в фото — вырезать при сжатии.
- **Память/батарея**: не держать превью полноразмерными; Glide + thumbnail.
- **Совместимость**: старые версии приложения получат сообщение с вложениями — покажут пустой пузырь; стоит добавить fallback «Вложение» хотя бы в новых версиях, а старым — ничего не сломать (тип сообщения не TEXT).

## 8. Принятые решения

1. **Смешанный список**: в одном сообщении можно прикрепить до 10 файлов любых разрешённых типов (фото + видео + аудио + документы вперемешку).
2. **Без подписи**: отдельного текста (caption) к вложениям нет.
3. **Только выбор из телефона**: галерея и системный файловый менеджер, без съёмки камерой. Отдельные разрешения не нужны — Photo Picker и SAF.
4. **Лимиты**: как в разделе 3 (фото 15 МБ, видео 64 МБ / 3 мин, аудио 20 МБ, документы 20 МБ).
5. **Голосовые**: до 5 минут, запись по удержанию, отпустил — отправил.
6. **Видео-кружки**: фронтальная камера, до 60 секунд.
7. **Документы**: только скачивание, без встроенного предпросмотра PDF.

## 9. Порядок работ

Сначала полностью закрываем вложения (разделы 2.1–2.2, 3–5), затем отдельным
релизом — три режима кнопки и запись голоса/видео-кружков (раздел 2.3).
