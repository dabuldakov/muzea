# Google Play: соответствие требованиям UGC и удаление аккаунта

Документ фиксирует, как приложение закрывает требования Google Play к
пользовательскому контенту (UGC) и удалению аккаунта. Обновлять при изменении
эндпоинтов, экранов или публичных адресов.

## 1. Удаление аккаунта

| Что | Где |
|-----|-----|
| Удаление в приложении | «Профиль» → «Удалить аккаунт» |
| Публичная страница (RU) | https://muzea.su/delete-account |
| Публичная страница (EN) | https://muzea.su/en/delete-account |
| Исходники страниц | `muzea-legal/delete-account/`, `muzea-legal/en/delete-account/` |
| Срок удаления | сразу в приложении; до 10 рабочих дней по email |
| Резервные копии | перезаписываются в течение 7 дней |

Страница должна быть загружена на хостинг `muzea.su` (31.31.196.115) вместе с
остальными файлами `muzea-legal` и доступна без установки приложения. URL
указывается в Play Console → App content → Data deletion.

## 2. Жалобы на контент (UGC)

### Что можно пожаловаться

| Раздел | Действие в приложении | Тип в API |
|--------|-----------------------|-----------|
| Чат | долгое нажатие на сообщение → «Пожаловаться» | `MESSAGE` |
| Чат | долгое нажатие на сообщение → «Заблокировать» | `POST /api/blocked` |
| Новость | кнопка «Пожаловаться» на экране новости | `NEWS` |
| Видео | кнопка «Пожаловаться» на экране видео | `VIDEO` |

Причины: `SPAM`, `ABUSE`, `VIOLENCE`, `ADULT`, `ILLEGAL`, `OTHER`.
Свои сообщения/новости/видео пожаловать нельзя.

### API

- `chat-muzea`: `POST /api/reports` (Bearer), тело
  `{contentType: MESSAGE|USER|CHAT, contentUuid, reason, comment?}`.
- `api-muzea`: `POST /api/reports` (Bearer), тело
  `{contentType: NEWS|VIDEO, contentId, reason, comment?}`.
- Обе ручки идемпотентны: повторная жалоба того же пользователя на тот же
  объект возвращает уже созданную запись.

### Хранение

- `chat_db.content_reports` — миграция `V17__content_reports.sql`.
- `makeup_db.content_reports` — миграция `V4__content_reports.sql`.
- Поля: автор жалобы, тип и id контента, автор контента, причина, комментарий,
  короткий снимок текста/заголовка, статус (`NEW`/`REVIEWED`/`ACTION_TAKEN`/`REJECTED`).

### Модерация

1. Оператор периодически смотрит жалобы со статусом `NEW` в БД.
2. Проверяет контент по `content_uuid` / `content_id`.
3. При нарушении удаляет контент и/или блокирует пользователя; статус меняется
   на `ACTION_TAKEN`, при отсутствии нарушения — `REJECTED`.
4. Пользовательское соглашение (раздел 6.1) описывает жалобы, срок рассмотрения
   (до 10 рабочих дней) и право оператора удалять контент и ограничивать доступ.

## 3. Осталось для Play

- [x] Загрузить `muzea-legal` на хостинг и проверить `/delete-account`
      (веб-корень reg.ru `/www/muzea.su`, скрипты `deploy.sh` / `verify.sh`).
- [ ] Указать URL удаления аккаунта в Play Console:
      `https://muzea.su/delete-account`.
- [ ] Заполнить Data safety: жалобы и удаление аккаунта.
- [ ] Добавить тестовый доступ для ревьюера (OTP-вход): временный аккаунт или
      фиксированный код только для review-сборки.
- [ ] Проверить, что в Play Console указана ссылка на политику конфиденциальности
      и контакт разработчика.
