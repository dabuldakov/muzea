# AGENTS.md

## Git и релизы

- **Не коммитить, не создавать теги и не пушить** изменения без явной команды
  пользователя («коммить», «пуш», «релиз» и т.п.).
- По умолчанию изменения остаются локальными: сначала показываем результат,
  ждём подтверждения.
- Релиз (тег `v*`) создаётся только по отдельной команде.
- Секреты и keystore (`muzea.jks`, `keystore.properties`, пароли) в git не
  добавлять.

## Коммиты, деплой и changelog

- Любая задача заканчивается коммитом. Перед сборкой, деплоем или релизом в
  рабочем дереве не должно оставаться незакоммиченных изменений.
- Тема коммита — conventional commit и одновременно строка «Что нового»:
  `type(scope): результат` по-русски, с заглавной буквы, без точки.
- Типы: `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `build`, `ci`,
  `style`, `chore`, `revert`. Версия оформляется отдельным коммитом
  `release: 1.7.22` — в список изменений он не попадает.
- `scope` — короткая область: `chat`, `contacts`, `participants`, `ui`,
  `update`, `data`, `release`.
- В теле коммита: что изменилось и почему, какие тесты добавлены/прогнаны,
  что задеплоено, какие данные или строки БД правились (с SQL, если правка
  разовая).
- Тесты к изменению идут в том же коммите. Отдельный `test:` — только когда
  меняются исключительно тесты.
- В теме коммита указывается код области из `docs/FEATURE_CATALOG.md`:
  `fix(chat): ... [MEDIA.07]`. Если кода нет — сначала добавь пункт в каталог.
- Каждое изменение попадает в `docs/WORKLOG.md`: дата, версия, тип, код,
  короткий результат и коммит. Релизный коммит закрывает записи версией.
- Разовые правки прод-данных (без изменения кода) фиксируются коммитом
  `fix(data): ...` с SQL в теле — чтобы правка осталась в истории и попала
  в changelog. Миграцию в код не добавлять, если правка не для всех
  окружений.
- Перед пушем: `testDebugUnitTest` / `integrationTest` зелёные, release
  собирается, `versionName` совпадает с тегом.
- Порядок релиза: коммиты задачи → коммит `release: X.Y.Z` → тег `vX.Y.Z`.
  Список изменений генерируется из коммитов между тегами.
- Деплой и пуш выполняются только после явной команды пользователя; но если
  команда получена — сначала коммит, потом деплой, без «забытых» файлов.

## Работа в чате «Баги»

- Мост прикладывает к каждому сообщению историю чата с последнего ответа
  бота — не терять контекст обсуждения.
- Перед релизом (тег, публикация, выкладка) явно спросить подтверждение у
  пользователя, даже если ранее была команда «сделай всё».
- Перед длительной работой (разбор бага, тесты, сборка, работа в фоне)
  обязательно написать в чат: «Ухожу проверять/тестировать/собирать…».
  По завершении — «Вернулся: …» и короткий результат. Это касается и
  случаев, когда работа идёт без видимых сообщений несколько минут.
- Любой фикс по умолчанию сразу собирается в beta-APK (в имени файла
  `beta`) и выкладывается файлом в чат «Баги» без отдельной команды.
  Ссылки на сторонний сайт вместо файла не использовать.
- Релиз (тег/публикация) — только после явного подтверждения пользователя.
